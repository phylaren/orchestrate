# Звіт: розгортання та зовнішня перевірка Orchestrate

## 1. Поточний стан

Застосунок запускається локально або в Docker Compose. Для демонстрації зовнішнього доступу локально запущений застосунок відкривається через тимчасовий ngrok-тунель.

| Компонент / можливість | Поточний стан |
|---|---|
| Spring Boot застосунок | Реалізований; HTTP-порт `8080` |
| PostgreSQL | Сервіс `postgres:17-alpine` у Docker Compose |
| Dockerfile | Multi-stage збірка на JDK/JRE 25; застосунок працює від окремого непривілейованого користувача |
| Compose | Запускає `app` і `postgres`; PostgreSQL має healthcheck, застосунок чекає на готовність БД |
| Публічний вхід у Compose | Не налаштований: порт `8080` має лише `expose`, без публікації на хост |
| Ngrok | Можна запустити вручну до локального застосунку командою `ngrok http 8080` |

## 2. Архітектура

### Docker Compose

```text
Docker Compose
├── app       Spring Boot, профіль prod, внутрішній порт 8080
└── postgres  PostgreSQL 17, дані у томі postgres-data
```

Compose не публікує порт застосунку на хост: контейнер `app` оголошує `expose: 8080`, але не має `ports:`. Застосунок у Compose доступний іншим сервісам його мережі, але сам по собі не доступний з браузера або ngrok, запущеного на хості.

### Ручний тунель для локальної перевірки

```text
Інтернет ── HTTPS ──► ngrok ── HTTP ──► локальний Spring Boot :8080
```

У перевіреному сценарії застосунок запущено безпосередньо на хості, а ngrok спрямовує трафік на порт `8080`. Ngrok надає зовнішню HTTPS-адресу для демонстрації та тестування.

## 3. Запуск застосунку

### Локально, для роботи з ngrok

У першому терміналі з кореня репозиторію запустити застосунок:

```bash
./gradlew bootRun
```

За замовчуванням локальний профіль використовує H2 і слухає порт `8080`.

У другому терміналі запустити тунель:

```bash
ngrok http 8080
```

Після запуску ngrok використати надану ним HTTPS-адресу для перевірки API:

```bash
BASE_URL='https://<адреса-ngrok>' sh scripts/security-check.sh
```

У PowerShell еквівалентний виклик:

```powershell
$env:BASE_URL = 'https://<адреса-ngrok>'
sh scripts/security-check.sh
```

Якщо застосунок запущений у Docker Compose, команда `ngrok http 8080` на хості не матиме доступу до контейнера за поточною конфігурацією. Для такого сценарію потрібно окремо налаштувати доступ до контейнерного порту або розмістити тунель у тій самій Docker-мережі.

### Docker Compose

```bash
cp .env.example .env
# Відредагувати .env і задати реальні значення замість прикладів.
docker compose up -d --build
docker compose ps
```

Обов'язкові налаштування включають параметри PostgreSQL, `ORCHESTRATE_JWT_SECRET`, `ORCHESTRATE_NOTIFICATION_WEBHOOK_URL` і `ORCHESTRATE_SECURITY_CORS_ALLOWED_ORIGINS`. Файл `.env` містить секрети, не має потрапляти до Git і не повинен використовувати демонстраційні значення у production.

У Compose застосунок працює з профілем `prod`, використовує PostgreSQL і Flyway для міграцій. Healthcheck PostgreSQL перевіряє готовність бази; healthcheck застосунку виконує запит до `/login`.

## 4. Контейнеризація та завершення роботи

`Dockerfile` збирає виконуваний JAR в окремому build-етапі на JDK 25 і запускає його на JRE 25. Процес працює від системного користувача `orchestrate`, а `ENTRYPOINT` заданий у exec-формі, тому JVM отримує сигнал завершення напряму.

У базовій конфігурації Spring увімкнено graceful shutdown:

```properties
server.shutdown=graceful
spring.lifecycle.timeout-per-shutdown-phase=30s
```

Для контейнера в `docker-compose.yml` задано `stop_grace_period: 40s`, щоб дати застосунку завершити активні запити в межах таймауту Spring.

## 5. Автоматизована перевірка API

`scripts/security-check.sh` перевіряє базовий сценарій авторизації та доступу до домогосподарства:

1. Запит до `/api/v1/users/me` без токена має повернути `401`.
2. Скрипт реєструє тестових користувачів і отримує JWT через login.
3. Запит з токеном має пройти, власник створює домогосподарство та код запрошення.
4. Мешканець приєднується за кодом; власник читає зведення дозволів, мешканець без `MANAGE_MEMBERS` отримує `403`.

Публічну перевірку запускають із `BASE_URL`, що вказує на ngrok-адресу. Скрипт створює тестові облікові записи й дані в базі, до якої під'єднаний застосунок. У локальному сценарії це H2; у Compose з профілем `prod` — PostgreSQL.

Під час перевірки на Windows вміст запиту створення дому передається ASCII JSON із Unicode escape-послідовностями, щоб уникнути проблем кодування кирилиці в оболонці. Користувач підтвердив успішний запуск перевірки через ngrok після цієї зміни.

## 6. Обмеження та наступні кроки для повного deployment

Ngrok-адреса є тимчасовою і придатна для демонстрації, а не для постійної експлуатації. Docker Compose ізолює застосунок у внутрішній мережі й не публікує порт `8080` на хост; для зовнішнього доступу до контейнерного застосунку потрібна окрема конфігурація публікації порту.
